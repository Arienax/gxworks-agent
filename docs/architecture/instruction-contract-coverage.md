# FX3U instruction contract coverage

## Contract dimensions

The generation catalog, native encoding, operand signature and verified behavior are distinct data. [InstructionRegistry](../../src/plc/instructions.py) resolves an admitted literal opcode form for a CPU; `InstructionSpec.describe_contract` exposes the available contract dimensions.

Dimensions include applicability, arity, operand order, roles/types/device classes, execution form, operation width, execution conditions, completion ownership and memory/numeric limits. Missing facts remain unresolved; legacy declarations retain their unverified classification.

The runtime promotion ledger is [fx3u_contract_promotions.json](../../resources/instructions/mitsubishi/fx3u_contract_promotions.json). Current counts and per-form reasons are generated by [audit_fx3u_contracts.py](../../tools/audit_fx3u_contracts.py), not maintained as a second table here.

## Evidence and promotion

The auditor reads the source database without rewriting it and checks manual identities against [sources.json](../../resources/knowledge/sources.json). A promotion requires a complete native instruction-format/set-data signature and independent explicit ST-call corroboration from the matching instruction section. The native operand order is retained even when an ST wrapper uses a different order.

Literal forms must agree in the source mnemonic tables. Conditional/composite cells, incomplete symbols, conflicting arities and unrelated examples remain unresolved. Signature agreement does not promote operand types, writable ranges or hardware completion rules; each dimension needs its own evidence.

[InstructionRegistry.resolve](../../src/plc/instructions.py) selects CPU-scoped overrides. The generic validator and repair filtering consume that same view. Model-neutral import preserves unknown vendor records without admitting them for new generation.

## Reproduce

With dependencies installed and LFS knowledge data present, run from the repository root:

```powershell
python tools/audit_fx3u_contracts.py --report fx3u-contract-audit.json
python tools/audit_fx3u_contracts.py --check
python -m pytest -q tests/test_instruction_contract_alignment.py tests/test_instruction_registry.py
```

Review the generated per-form report before using `--promote`, which rewrites the promotion ledger. `--check` compares the checked-in ledger with reproducible results. Source hashes, manual revisions and failure reasons belong to the generated report. Historical batch results are linked from [version reports](../reports/README.md).
