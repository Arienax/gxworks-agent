# 已确认行为的构造与有界检查

行为关系保存在确认规格的可选 `behavior_constraints`，实现选择保存在
`selected_approach.construction_plan`。旧工程没有这些字段时沿用既有生成路径。
[behavior.py](../../src/plc/specification/behavior.py)复用 `Expression`、`ValueType`
和操作效果，保留每项要求的用户原文与确认来源；候选关系不能自行变成已确认要求。
Agent A在原有分析调用中提出候选，规格编辑器负责确认，不增加规划调用或自动Design。

构造计划只选择方法、依赖及明确允许的内部区域，不保存整道工艺题的程序。
[construction.py](../../src/plc/construction.py)检查具体CPU事实、执行条件、资源占用、
地址范围和写入归属，再实例化以下方法：

| 方法 | 固定关系 |
| --- | --- |
| `first_scan_isolation` | 首扫描结束保持已确认的位、字及输出初值，隔离会重写这些目标的正常路径；未受保护的监视路径仍可执行 |
| `source_history` | 原始信号取沿与接受条件分开；按确认的启动策略采样源沿，不把许可恢复当成新事件 |
| `scan_union` | 单扫描事件合并一次，连续扫描的不同事件分别处理；结果不再次取沿 |
| `priority_snapshot` | 先保存组内条件和效果所需旧值，按确认顺序选择一项转换，再执行关联效果；独立组按程序顺序分别执行 |

内部状态只从显式M/D区域分配，避开用户引用、初始化目标、效果占用、多字范围及既有
工程占用。来源记忆与要求清零的工艺状态必须分开声明。没有适用事实或可用资源时记录
缺口并保留草稿，不借用相近型号的事实。

compact输出在梯级位置允许 `{"construct":"实例ID"}`。Core检查次数、完整性、依赖
顺序、自由部分的重复写入和事件再次取沿，再展开进入原有OP绑定、IR和校验。
[prepare_model_candidate](../../src/application/generation_agent.py)使用运行时拥有的CPU，
不从不含CPU的规格正向投影推断型号。构造回执保存在版本生成元数据中；参考范例的
原有开关与实际构造相互独立。

## 事实与执行范围

[control_runtime.json](../../resources/instructions/control_runtime.json)保存具体CPU、手册
修订、页码及条件。构造器、事实检索和检查器消费同一来源。本版只启用有证据的FX3U、
FX5U控制子集；其余型号入口保留未验证。FX5U首扫描须明确为scan execution且没有
initial execution程序；普通`OUT T`采用100ms时基，`OUTH`、`OUTHS`分别为10ms、1ms，
不按T地址分段。FX3U普通定时器仍按已记录地址范围选择时基；保持定时器不属于本版。
应用指令只解释已有Registry中来源核对完整的效果闭包；缺失语义不由检查器补规则。

[bounded.py](../../src/simulator/bounded.py)复用`lower_rung_instructions`按实际IL顺序
执行共享条件、即时写入和后续读取。已有内存后端继续作为测试替身。本检查器提供有界
软件执行证据，不代表原生仿真或真实PLC验收。

自动检查枚举显式初值和有限输入组合，每项最多4096条、每条最多8扫描，并记录截断。
未声明内存保持未知。定时器使用显式累计毫秒或声明的单调时间观察；不把扫描次数换成
经过时间。额外冻结时间轨迹单独执行，并保留初值、时间及进展预期。检查范围包含首扫
重写、源沿与启动策略、相邻事件、重复转换、停止／完成竞争、互斥和正常推进；这些
局部检查不替代完整工艺审阅。

重复转换只计算确定发生的写入。未支持的操作数形式即使opcode已知，也不能假定没有
写入；无法确定写入范围时将相关反例隔离为`unverified_witnesses`并保留未验证状态，
不把基于未更新内存的推断作为激活阻断依据。位组传送的执行语义当前未启用。

## 版本与交付

结果区分`violated`、`no_violation_found_in_tested_scope`、`unverified`。缺事实、不支持
的指令、未知值、预算耗尽和检查器异常保留各自原因；供应商传输失败由生成记录保留，
不转成模型改写请求。本轮不自动局部修复。

反例绑定要求ID、程序版本、扫描前状态、输入序列及具体IL写入位置。保存与激活沿用
SessionStore版本流程：明确违反已确认关系的候选保留诊断版本并阻止激活；未知项保留
未验证。修改候选后重新检查，旧反例不能沿用为新版本结论。Web与MCP共用回执和交付
摘要，全文检查范围、假设及反例保留在该版本的`behavior_check`。

规格正向投影不包含运行时CPU；构造说明、候选展开和检查必须分别使用生成入口或IR
拥有的确切型号。IR与规格型号冲突或缺少该CPU事实时不执行检查，记录零覆盖与未验证
原因。交付摘要展示实际轨迹数、反例写入位置、构造引用冲突及未验证原因。

实测操作与结论边界见[Agent B测量指南](../guides/agent-b-measurement.md)。
本轮72项两接口结果及独立离线复核见[实验报告](../reports/2026-10-05-core-construction-value.md)。
