## 改动

### 规格交互

- 最新分析完成且工程、版本、确认规格哈希仍匹配时，直接打开已有规格编辑器。
- 不覆盖用户正在修改的草稿，不重复应用同一任务的草稿；旧任务和过期规格继续走显式打开和冲突检查。
- 编程方案显示为单选卡片；问题的候选答案直接显示为按钮，保留自定义输入。建议值仍不是已确认答案。
- 默认 Agent 页面移除 JSON 字段列表，完整数据编辑只保留在折叠的高级区域。

### 实时进度与预览

- `ResponseProgress` 在请求开始、收到思考、收到正文、检查回复格式时立即发出。工作台每 0.4 秒最多持久化一次同阶段更新，阶段切换立即发出。
- 前端显示不标百分比的活动进度条、实际阶段和已用时间；没有根据 token 数推测完成百分比。
- “查看实时输出”默认折叠，展示独立的 `model_preview` 事件，明确标记为生成过程预览。只有思考和正文能进入预览，工具调用不经此通道发布。
- 每次新请求清空前一次预览；回复或传输失败时发送 discard，界面清空对应预览。失败输出不会作为正文回调、规格草稿或可执行工具交付。
- 可选预览上限为 64000 字符，并显示截断说明；限制只作用于预览，不改变完整响应、程序或最终产物。
- 已验收的文本通过 `ModelJobContext` 合并后写入任务记录；这不改变 Provider 原有回调契约，且与实时预览独立。实测第一版为一条正文的 1457 个小片段重复写文件，优化后正文仅写一条，避免生成后的收尾等待。

### 语言与结构边界

- 工作台任务在 `response_policy_scope(enforce_language=False)` 内执行，保留语言提示，只放宽语言脚本匹配规则。
- JSON 语法、根对象类型、声明的人类字段类型、工具参数结构仍严格检查；FBD 的原生对象、端口、连接、声明及产物一致性继续经过原有确定性校验。
- 既有严格调用方保留默认策略；策略随 `ModelRequest` 冻结，并通过 ContextVar 隔离并发任务，不作为模型服务请求参数发送。
- 可写入工程的候选仍需审批，GX Works2 编译状态不能因这些检查而标成通过。
