# 界面与输出语言

> 本文保留旧 Qt 界面时期的说明，不是当前 UI/模型语言规则。Qt 已退役；当前入口见 [Web 指南](integrations/web.md)，模型接受策略见 [响应语言](architecture/response-language.md)。

右上角统一的「设置」按钮包含 API 设置、API 高级设置和语言。
支持简体中文（默认）、English、日本語；保存后刷新当前界面并持久化到配置文件。
只修改语言不要求提供 API Key，也不会改写或删除已保存的凭据。
为保持一次任务的语言一致，任务运行期间不能打开设置。

## 输出约束与数据边界

- 每个模型请求记录发起时的语言；同步、流式、工具调用及非流式重试使用同一语言策略。
- 模型的解释、推理摘要、问题、标题及结构化响应中的自然语言说明遵守所选语言。
- JSON 字段名、枚举、工具名、PLC 指令、软元件地址和用户提供的代码保持原样。
- 流式显示按句子或行检查明显的错误语言，并显示当前语言的提示；原始模型响应和测试证据不会被此显示检查改写。
- 用户原文、已有程序、历史回复和原始诊断证据不做追溯翻译。

语言策略是对模型的请求约束，不是任意文本的机器翻译器。显示检查使用保守的字符和词形规则，
不能可靠识别所有混合语言、引用或不带假名的日语片段。第三方模型的实际遵循情况仍需使用用户配置的服务验证。

## 开发维护

`src/i18n.py` 提供语言上下文、可延迟翻译的 `tr()` 文案、状态翻译和响应语言策略。
`resources/locales/en.json`、`ja.json` 使用中文应用文案作为键；占位符必须与源模板一致。
动态用户值通过占位符传入，不能拿用户输入、协议字段或标识符当翻译模板。

`src/qt_i18n.py` 仅绑定显式标记的应用文案，语言切换不重建编辑器或改写控件的内部选项值。
文件选择框使用 Qt 对话框，以便跟随应用语言而不是 Windows 显示语言。
两个打包配置均包含应用词典及 Qt 中文、日文对话框资源。

`tests/test_i18n.py` 验证词典占位符、界面更新、设置保存和取消、请求语言快照、重试、
流式显示及原始数据保护；现有模型传输测试仍验证图片与推理回放。
