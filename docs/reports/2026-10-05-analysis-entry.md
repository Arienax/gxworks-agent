## 实现与可复现回归

`resolve_answer_bindings` 接收当前行、历史绑定和整批答案，先收集地址，再关联同一明确身份的极性/电平；返回逐题结果、合并属性、移除状态和冲突。`validate_spec_draft` 与 `bind_answers` 使用同一规则，每个绑定只写一次。保留 Core 的地址规范化及型号校验、改址优先、删除不复活、显式物理行共用和非地址语义参数边界。不同地址、矛盾电平或不同物理 owner 占同地址均报错；全批次移动先于占用检查，合法换址不受题目顺序影响。

在线响应另外暴露了元数据省略：属性题只引用 `binding_id`，或者完整地址题未写 `kind`。Core 保留明确逻辑身份；缺失元数据可来自同身份题目，类别也可来自用户实际回答的地址。角色不从自然语言标签猜测。已明确但相互矛盾的类型或属性不会由后一个答案覆盖。

需求阶段保留原始要求、明确时序/恢复约束及用户写死的限制，只提取控制意图、Direct 的一个实现方向、逻辑 I/O 和必要问题；不加载地址化效果、行为关系和构造协议。具备设备事实的阶段使用相应协议，历史或已删除绑定本身不能使阶段升级。未齐 I/O 必填项仍使用需求阶段，模式选择和模型调参所有权保持独立。

只有形状及当前原文证据有效、唯一错误为来源设备缺失的可选执行候选进入 `pending_binding` 诊断，执行约束为空；填写地址不会把它升级成要求。其他协议错误仍只允许一次修复。诊断包首个响应的流式、非流式回放均只调用模型一次，确认表可用，没有伪造设备。明确上升沿要求保留；普通起保停的生成不增加边沿或恢复后重新按启动的要求。

回归覆盖常开/常闭 × 全部 24 种题目排列、地址类 choice、非地址语义 choice、同绑定与跨用途冲突、任意绑定标识、合法小写/补零别名，以及最多八步的改址、极性修改、删除序列。FX3U 的 `X8` 拒绝、FX5U 的 `X8` 接受分别验证了型号边界。

HTTP 回归实际经过分析作业、填表、一次确认、保存回读、首次生成、改址后生成、删除后生成。常开停止保存 `active_level=1`，生成请求携带 `active_when=NO X0`、`run_permit_when=NC X0`；常闭对应相反谓词。删除后不再有停止绑定、谓词或程序运行引用。既有编辑协议可以保留旧注释声明，测试没有把这种历史注释当作活动 I/O。

## 确认、保存与生成结果及失败

首次在线过程中，初版填表器要求完整类型元数据，四份新组响应未继续确认；只有新组第三轮直接完成确认与生成。失败与原程序均保留在 `runs/`，不能将后续结果称为首次在线全路径 5/5 成功。

补齐归属规则和填表器后，使用原已接受响应，在独立工程中再次经过 HTTP 分析作业、填表、确认和回读。分析供应商由原响应回放替代，不发送新分析请求；回放的约 0.7 秒耗时不进入上面的在线对照。旧组仍运行原 Core。填表器只采用问题中的明确角色来填写固定的 X1/X0/Y0 和常开事实，不修改方案或补造绑定元数据。

旧组第三、第五轮被后端以 `invalid_io_answer` 拒绝；第一轮因模型使用了错误的类型词，原草稿丢了角色元数据，虽能保存但没有正确的停止谓词。上述失败分别保留，未用模型或本地代码静默改写旧方案。

新组第三轮复用首次在线生成，其确认后的公开生成上下文经比较完全一致；另外四份在确认回放后各实测生成一次。五份生成总耗时依次为 **3.910、7.361、2.340、3.956、2.525 秒**，中位数 **3.910 秒**、范围 **2.340–7.361 秒**；各一次调用、返回 `deepseek-flash`，不混入分析耗时。

五份实际产物均为 `(NO X1 OR NO Y0) AND NC X0 → COIL Y0`。独立预期 `next_Y0=(X1 or previous_Y0) and not X0` 对每份覆盖两种初态与四扫描输入序列的全部 512 种组合，均通过；持续启动、停止优先及停止释放后仍按住启动的情况均包含其中。该检查是 Core 有界扫描模型，不是原生仿真或真实设备验收。

最终源码还补了已有 owner 的地址占用检查，相关 Core、性质测试及完整 HTTP 回归另行通过。这部分不影响新建空表的提示词或供应商参数，但最终补丁没有再发起一套新在线分析；上表的分析本地耗时仍以首次冻结入口为准。
