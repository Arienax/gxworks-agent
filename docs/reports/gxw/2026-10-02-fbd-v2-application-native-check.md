# FBD v2 应用贯通与当前代码检查快照

日期：2026-10-02。工作树基线为 `ef0a255`，v2 Core 的相关源码与 2026-10-01 冻结接口从 `5b39c13` 选择性接入。环境为 Windows、Python 3.13、安装在 `D:/GXWORKS2` 的 GX Works2，以及隔离的 x86 辅助进程。CompilerAdapter、Workspace、Compiler_IEC 的文件版本均为 `1.635.0.1`。没有 PLC 或仿真器执行，也没有提交、推送或发布。

## 应用行为

[read_project_context](../../../src/gxw/object_model.py)统一绑定当前 GXW 字节、所选 Program、声明和 CPU。目录、对象投影、草稿端口、预览与候选校验均从该上下文构造。待保存的声明用于重新解析接口，原始端口字段仍作为只读来源；接口数量与原记录不一致时拒绝写入。保存后的读取再次从新 GXW 构造 v2 投影。

Web 编辑器与共享 Agent／MCP 工具复用此入口。现有自定义 FB 的实例重命名同时修改图形引用与声明；双向形参使用 `in.NAME`、`out.NAME`。候选继续进入现有审批流程，返回 `gx_compile=not_run`。本报告的原生结果来自独立的隔离研究进程，不提升产品候选的自动验证状态。

应用验收包含正确端口、双向端点分别连接、预览／保存／回读一致，以及一个有明确边界的 12 字节未知记录与已知对象共同编辑。未知记录用例属于合成回归，不证明任意未知原生对象都被厂商接受。

## 批量边界

批次复用 69 个原生 CPU 菜单选项的完整模块、7 个 FX 类型对照和 5 个项目 FB 对照，共 81 项输入。完整模块包含两个 TON、自定义项目 FB、BOOL、STRING[20]、WORD 双向参数、实例重命名、具名连接与图形移动。不同对照的通过范围分别保留。

| 观察 | 结果与范围 |
| --- | --- |
| 应用中的自定义 FB 实例闭环 | 67 项通过；最终 Core 重新生成的候选字节 67／67 一致 |
| 没有原生工程输入 | 10 项原生工厂失败，保留失败，不算应用通过 |
| 原测试缺少 MODULE_FB 调用 | 4 项 `StopIteration` 保留；原输入已有 TON 接口缺口 |
| 上述 4 项的局部编辑对照 | 修改已知输入 X0→X1 后保存回读一致，未解析调用记录与缺口保持；未重新宣称原生模块通过 |
| 原生编译、检查、保存、冷重开 | 55 个不同 CPU 菜单选项通过；图形记录、声明行与重开代码逐字节一致 |
| 检查器实际读取资源 | 对 FX3U/FX3UC、Q03UDV、L02 插桩；读取的三个通道与本次编译输出一致 |

55 个选项中包括 FX 类型收窄对照和 FX0N 项目 FB 对照，不能写成 55 个选项都接受完整 STRING／TON 模块。其余 52 个选项没有本次读取插桩。组合菜单名称不等于分别测试了每个物理型号。Q03UDV、FX3U/FX3UC 的结果均不推广到整族。

完整 CPU 结果、原生拒绝、工厂失败、最初的调用缺口和启动目录冲突见[机器可读结果](../../../research/results/gxw-fbd-application-v2-20261002.json)及证据包中的 `cpu-module-boundaries.json`。原生 CPU 参数来自各选项的新建工程，未通过修改 Q03UDV 模板的 CPU 字段代替。

## 诊断转换与负向约束

Q03UDV 原有语料中 26 个工程的原／改检查共 52 次 `0x2d010025` 失败，均在底层诊断已经返回后发生。只读跟踪定位到 CompilerAdapter `0x8e48`：底层 `instance_kind=6` 被转换为类别 `32`，经 Workspace 槽 `1784` 查找 `MAIN`。Workspace `0x793aa` 的实现对此类别先取程序集合 `25`；原工程的实际 POU 名称没有 `MAIN`，查找失败。

受控实验只在原生隔离工作区把一个 POU 改名为 `MAIN`，三个编译输出通道完全不变，公开检查随后完整返回拒绝与原错误。之前仅改离线名称的失败对照仍保留。该实验说明名称映射的因果关系，不能作为产品改名修复，也没有认证返回的源码位置。

同一重复输出 FBD 模块在 FX3U/FX3UC、Q03UDV、L02 上都返回底层错误，随后诊断投影失败。此机制与本批资源／程序命名关系有关，不能称为只属于 Q 的行为，更不能推广到所有工程。

Q03UDV 的另一个隔离对照从已保存的有效工程修改 Y10→Y0：独立取得的新编译缓冲区与检查器读取的旧工作区缓冲区不同，公开检查却通过。检查完成与当前代码受检因此保持两个字段。FX3G 的旧／新发布双线圈对照、SFC 空任务返回缓存，以及上述诊断转换失败进入同一个冻结负向语料。

[program_check_evidence](../../../research/program_check_evidence.py)分别投影源码／配置选择、编译、发布、实际读取、各目标、底层完成、公开检查、诊断转换、保存和重开。尺寸查询与数据读取分开；空诊断列表在投影失败时不表示无错误。该工具读取保存的观察，不执行 GX，也尚未自动证明整条源码／任务／配置选择链。实例级源码位置与 BOOL 的执行语义仍未收口。
