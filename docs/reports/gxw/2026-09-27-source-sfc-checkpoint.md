# 源声明重建与 SFC 源图阶段快照

日期：2026-09-27。基线提交：`d1f5f3bd8c5cc14a7056590994d555f1d9da917b`。固定的是上次源分配快照之后的工作区源码、实验输入、原生输出和失败记录。环境为 Windows、Python 3.13、本机 GX Works2 与隔离 x86 辅助进程；DLL 身份和工作区状态进入清单。此次归档不重新运行原生编译，不提交、推送或发布。

## 已记录能力

Q 系列模型已从源声明恢复地址分配及有界调用连接，并在 Python 中计算观察范围内的指令宽度。冻结的真实语料 portable-v4 比较中，60 个程序记录有 58 个完整 PCode 与独立原生输出逐字节相同；剩余两个程序的原始声明缺失保留为失败，后续显式修复对照单独留存。Project2、SCPI 重复调用、条件连接、数组及声明顺序等实验的输入、预测和原生结果同时归档，不能将这些变体计作独立真实项目。

产品 Q 梯形图扫描记录为 36 个项目、76 个程序、7,492 条已解码指令，已检查范围内没有指令缺口，36 个容器均可逐字节重建。这不是全部语言或全部流的语义覆盖率。80,171 个应用指令宽度对照中，32,384 个字节一致、47,779 个被原生拒绝、8 个特殊调度样本仍不支持；32,277 个数值边界对照中，7,955 个字节一致、24,322 个被原生拒绝。拒绝与不支持均不算通过。

新增真实工程暴露了中文／空白名称段及旧 token 外框。程序身份按项目元数据关联，而非只匹配 `.Program.pou`。旧外框和 SFC 子程序尾部的已观察变体保留原始字节；尚未映射的 RET token 不按名称猜测提升。

SFC 源展开模型覆盖本批 FX3U 与 Q00J 的已转换图，关联动作、转换条件及块号。块号来自本地声明字段；任务列表顺序、程序名称和内嵌 owner 均不等于块号。真实双块 SFC 及修改对照支持这一结论。空任务反例会使原生接口返回旧的、甚至被替换过的资源缓存，因此“进度 100% + 获得 PCode”不能独立证明已重新转换。

未转换 SFC 图的 21,512 字节源区现可保留原字节并读取网格、步骤、条件、跳转、结束节点及已观察连接。31 个快照中 256 个有效符号的字段与原生读取结果一致；5 个路径对照的 23 条边及已知缺口一致。比较只使用原生接口实际写入的字段，早期误计未写入字段的失败结果原样保存。其余属性表保持 opaque，不推断执行顺序或并行运行语义。

FX 跳转目标、动作编号及 Q 结束节点的局部修改，已有独立图转换、完整 PCode、原生 ProgramCheck、导出和重新加载对照。Q 的结束节点 kind 14 与跳转 kind 15 不可互换，即使数值都为 999；错误 kind 的拒绝对照保留。真实双块 SFC 原工程及其早期变体仍被完整 ProgramCheck 拒绝，不能用成功的图转换替代该失败。
