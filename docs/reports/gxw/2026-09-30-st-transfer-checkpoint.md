# 临时分配与 ST 参数转移阶段快照

日期：2026-09-30。本快照接续[当前检查与分配快照](2026-09-30-check-allocation-checkpoint.md)，固定后续保持区、表达式临时变量、条件连接、数组索引及 ST 参数转移实验。源码、环境身份、失败目录、输入输出哈希及前一快照关系见[清单](../../../research/results/gxw-st-transfers-20260930/manifest.json)。使用隔离工程和自有原生辅助进程；没有 PLC 或仿真器执行。

## 已恢复的规则

保持变量的源声明 class 10 可到达原生分配类别 6，补上此前 class 6 被拒绝后留下的缺口。保持池与普通池分别选择；D1／D2、W1／W2 的选择和耗尽边界见归档中的 `retain-class10-holdouts-20260930-v3`、`retain-source-model-20260930`。这些是限定 Q03UDV 工程的观察，没有提升为通用产品支持。

表达式临时变量首次申请时占用物理地址，释放后保留地址并供兼容类型复用。INT 与 DINT／REAL 使用不同槽类型；DINT 和 REAL 可共享双字槽。临时字池优先级为 ZR、R、W、D，与普通变量分配顺序不同；已选池耗尽不会在所测控制中回退。R 和 ZR 同配时，普通初始化抑制 ZR 描述符而临时选择仍优先 ZR，产生拒绝反例。平衡／链式表达式、宽度交替、循环和索引的原始槽事件、提前预测及初始错误预测都保留。

ST 动态数组 `VAR_IN_OUT` 先复制入临时值，块体结束后重算实参下标并写回；直接标量则是地址引用。动态 `VAR_OUTPUT` 在块体前设置索引寄存器，块体中的其他动态访问可能覆盖该寄存器，从而改变输出目标。在调用下标始终为 0 的控制中，仅交换内部读取与输出赋值的顺序，就使输出从数组第 0 项移到第 2 项。

嵌套数组读取也存在索引寄存器复用反例：初始化完全确定的 `a[a[i]] + a[a[j]]` 在所测输入上源算术为 12，生成指令的有限离线计算为 14。原始 token、独立原生指令解码和编码前的原生操作数描述共同定位到 Z16 复用；拆开求值的控制恢复为 12。这些证据证明所测编译行为，不能把检查通过表述为源语义正确。

## 验证范围与失败

三组 ST 参数索引实验共 17 个样本：15 个完成新鲜检查、导出和重开，2 个 `VAR_INPUT` 写入在前端拒绝。30 个实际检查阶段核对了当前 PCode、检查器读取字节及导出资源的两份代码。最后 4 组完整 PCode 在原生运行前保存预测并全部命中；此前 11 组源码模型拟合发生于观察之后，不能计作独立预测。

条件数值／字符串连接的较早 Simple/FBD 对照单独保存：34 个检查阶段中 28 接受、6 拒绝，另有 8 个检查前拒绝；16 份完整源码预测与当前代码一致。该集合与其他结果不相加为独立真实工程覆盖。ST 输入写入拒绝也不能外推成所有 Simple/FBD 输入只读。

索引插桩 v1 的守卫不匹配、v2 的进程提前终止和 v3 改用函数边界后的成功复核均归档。v2 没有捕获异常或退出码，因此更正记录不将其认定为 AccessViolation。原始失败文件未覆盖。

当前调用预测器仅处理已测 INT、有限数组和简单赋值调用。条件 ST 调用、字符串、嵌套 FB 和一般数组仍需扩展。它有意复现观察到的编译器行为，并非安全程序生成器。REAL 显示也不构成二进制往返保证，已有四个舍入反例仍保留。
