# 原生局部声明与 FBD 联合更新

日期：2026-10-04。原生组件为 `1.635.0.1`；CPU 扩测工程的代码页为 936。实验使用隔离工程副本，没有 PLC／仿真器执行、提交或推送。具体菜单选项、各阶段结果及原始调用见[机器可读摘要](../../../research/results/gxw-fbd-native-declarations-20261004.json)。

## 已验证的纵向能力

原生工作区中的局部声明创建、类型更新、变长重命名、删除和 FBD 源体更新已经形成可复用的研究路径。操作绑定当前工程、实际 POU 和对应的声明表，先核对原始源体，再调用原生接口修改；每次写入都通过原生 getter 读取当前源体。编译、资源发布、当前资源检查、原生保存和冷重开分别记录。

扩测复用上一模块的具体 CPU 工程。一个联合编辑删除原来的第二个 FB 实例及其图形调用，创建一个 BOOL 局部变量并将类型改为项目 `MODULE_FB`，将第一实例改为中文变长名称，再写入包含两个实例及 WORD IN_OUT 两侧的源图。两个调用分别输出到 Y1、Y2；输入 D50 和输出 D51 保留为不同图形端点。

该路径使用原始 `GetPOUBodyData(1692)`、`SetPOUBodyData(1688)`、`GetLocalVariableID(1748)`、`GetLocalVariableElementID(1756)`、`CreateElementData(1976)`、`DeleteObject(20)`、`SetObjectName(60)`、`SetVariableDataType(1552)` 和 `SetVariableClassKeyword(1644)`。选择的是 POU owner 26 的唯一 body 32 和对应 labels 28，并核对父对象；资源 `MAIN` 不充当 POU 名称。

原生函数、返回值和检查报告没有被替换。当前路径位于有界研究辅助程序，还没有成为产品原生写入服务或 Web／MCP 的编辑入口。

## Core 绑定修正与独立来源

独立来源来自 `Serhioromano/gxw2-libraries` 的既有工程，保留来源树 `bf050f3879c826c504bcbd39fdab99e32c8d9c0f`。工程包含 63 个库 POU，其中 58 个可调用接口；原始来源为 ST，研究中的 FBD 调用图由受控源体构造，不计为独立现实 FBD 工程。该组原生证据绑定 FX3G、CPU 521、转换器 15.31、组件 `1.635.0.1` 和代码页 1252，原始记录保留在摘要指向的本地实验目录。

原生接口将实例从 `FB_HYST` 改为 `FB_AM_EVENT_RESET` 后，保存声明的 `data_type` 已改变，但 `type_reference` 仍保留 `FB_HYST`。同步修改图形时编译、当前代码底层检查和冷重开均通过；只改声明或只改图形均被 `0x500c2015` 拒绝。新建实例又产生了 `type_code=0`、空 `type_reference` 的声明，接受编译和冷重开后这些字段仍不变。

Core 因此通过当前声明的 `data_type` 和当前 CPU 的唯一可调用源码解析接口，保留已观察的 0／15 类型字段及旧引用，不再用辅助字段是否完整来决定端口绑定。显式 FB 类型编辑沿用来源中的声明类别。未观察的字段值、普通变量与 FB 类型冲突、重复或缺失来源仍保留读取缺口；没有放宽为任意类型码。

相关五个测试文件合计 **546 项通过**，涵盖声明、对象模型、无损读取、工程写入及 Web FBD。研究属性测试以原始原生接口为独立预期，验证 200 个形参改名／方向编辑案例的类型、顺序、记录字段、IN_OUT 两侧及未编辑行字节；这些生成案例没有逐个进行原生编译或运行验证。已有原生样本通过共享应用的导入、v2 投影、候选校验和无修改字节回读；应用层没有调用这条研究写入路径。

## 具体 CPU 菜单选项的结果

按原生目录 API 和两个原生 CPU 表中的 **69 个 Q、L、FX 菜单选项**逐项保留结果；合并选项保留原始名称。在 59 个可加载工程中执行本轮联合编辑，55 个完成整个路径，4 个在写入后被编译拒绝。另 10 个保留已有工程创建失败，未运行本轮编辑。

**55 个选项**均验证了原生声明和图形联合编辑、源体精确读取、编译完成且接受、资源发布、底层检查完成且接受、原生保存和冷重开。每项核对实际工程 CPU 与菜单对应的原生参数 CPU 字段。检查器读取的三个资源通道均对应当次编译输出；检查结束标记明确指向资源 `MAIN`。冷重开后，源体、声明及三个编译通道保持一致。

本轮底层检查没有错误诊断；没有调用公开适配器的诊断转换。它不能证明 Q 的公开检查链已经修复。

## 对象和保存字段的边界

删除后的局部名字查询可以返回 HRESULT 0、错误码 0 和全零对象 ID；接口成功码不能证明对象存在。辅助程序继续核对对象类型、名字和父对象。原先误将这个返回约定当成删除失败的尝试一并保留。

55 个联合编辑中，新变量的现场对象 ID 第七个 DWORD 为 4，保存声明中的现有 `record_id` 字段却在 54 项中为 2，在 FX0N 中为 0。两者不能直接互换；这里记录差异，不推断这个保存字段的完整存储含义。实例选择继续通过当前名字和原始工作区接口完成。

所有新建／改型实例在保存和冷重开后保留 `type_code=0`、空 `type_reference`，但 v2 接口和原生处理仍正确。这是该模块跨具体 CPU 的实测事实，不是对其他缓存字段或其他声明类别的统一规则。

未编辑的局部行、其他声明表和已保留源体内容均核对原始字节。本轮受控图没有增加未知对象，不扩大既有 Core 未知记录保留测试的原生适用范围。现场多步修改失败后的事务回滚也未验证。

初版长目录控制在导入阶段返回 `0x2d020013`；缩短目录后同一来源的编辑和冷重开通过。不据此推断精确路径长度上限。辅助进程临时目录冲突的失败尝试也保留。
