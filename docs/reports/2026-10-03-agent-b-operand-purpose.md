# Agent B 操作数用途对照 · 2026-10-03

本轮使用已保存的 ModelScope 配置完成 **52 次真实模型调用**。用途绑定组首次可用 **26/26**，相同手册原文组 **25/26**；唯一语义错误是原文组一次 CMP 把阈值与实测值的位置对调。用途绑定组耗时中位数较低，但样本少、响应长尾明显，起保停的完全相同请求也有耗时差异，尚不能确认稳定的正确率或速度收益。

## 被测输入与交付

基线提交为 `e5aa05d4f2b49dc0334ac7c2e9b1d383ca59c36a`，测量对应其上的工作树。模型请求入口、用途解析和缓存释放的被测差异在实测前保存到仓库外的 `measured-working-tree.diff`。环境为 Windows、Python 3.13.14；运行沿用先前补齐已声明 `filelock 3.32.7` 的临时虚拟环境，启用 `PYTHONUTF8=1`。

服务端点为 `https://api-inference.modelscope.cn/v1`，请求模型为 `deepseek-ai/DeepSeek-V4.1-Flash`。现有配置经供应商请求解析器生成的非消息参数为 `model` 和 `stream=true`；没有额外设置 temperature、effort、输出上限或用量选项。实测后的配置回查确认保存的模型、端点和 `userModelSettings` 未变。当前构造范例设置为关闭，两组均沿用该设置。

[合成案例](../../benchmarks/agent_b_operand_purpose_cases.jsonl)包含 SFTL、WSFL、BMOV、CMP、IVCK、TCMP 各两个地址/参数变体，以及一个起保停对照。每个案例在每组重复两次，按 `seed=20261003` 随机串行排列，共 13 个案例、26 对请求。确认规格固定，直接进入 Agent B，绕过 Agent A 重新分析。

规格提供控制要求、地址和参数含义，没有预填完整操作数列表或 `instruction_instances`。预期值在顶层 `evaluation`，由手册定义和合成参数独立抄录，不进入模型请求。参考为 `JY997D16601 R`：SFTL PDF 页 305、WSFL 310、BMOV 258、CMP 247、IVCK 687–688、TCMP 565。IVCK 预设线路、串口及变频器配置已完成；TCMP 使用已有连续三 word 时间区。移位长度与每次移动量取不同值，源区与目标区不重叠。

`manual_text` 与 `usage_bound` 复用当前检索的同一上下文，只改变新增逐槽位候选用途及其绑定回执的交付。原文组保留已清理手册正文、原有型号事实、已验证顺序、角色、类型和已验证用途。该对照测量显式绑定的增量价值，不测量旧版本与新版本的综合差异。旧兼容组 `legacy_retrieval` 仍可能进入当前结构化检索，本次没有使用它。

联网前，现有生成流程与 Context Compiler 离线编译全部 13 对最终请求，再通过所选供应商的实际参数解析器检查；网络调用为零。实测后再次核对全部 **26 对实际请求**：

- 原文组最终请求不含候选用途绑定；12 个指令案例的用途组确有绑定。
- 去除这些绑定后，规格、手册正文、其他模型消息和请求参数相同；范例配置相同。
- 每次实际请求均与该案例、该组的离线请求一致。
- 起保停两组最终请求完全相同，均没有候选用途绑定。

所有案例的最终预算回执均未发生超预算压缩。该结果只覆盖本批请求，不能替代更长任务的预算交付验证。人工核对事实组未运行：本轮没有提供经操作者审核的 `oracle_evidence`，未用自动解析候选冒充人工事实。

唯一错误来自 `cmp-b / manual_text / repeat=1`：比较阈值与实测值的位置互换，改变了指定三位结果的方向。该候选 JSON、结构和既有确认合同检查均通过，独立操作数预期判为失败，未让“生成流程完成”掩盖语义错误。48 份指令候选另行复核：均只有指定指令输出，输入门控地址正确；SFTL/WSFL 使用上升沿，其他指令使用 ON 条件，没有额外线圈覆盖结果。

配对耗时差（用途绑定减原文）的中位数为 **−0.56 s**，26 对中 15 对用途组更快。起保停请求完全相同，原文组两次为 6.05/6.28 s，用途组为 3.63/5.68 s。这个对照揭示服务/生成波动；各组总体中位数的差异不能直接归因于用途绑定。

IVCK、TCMP 在两组均通过，说明这批冷门参数任务尚未区分出绑定效果。CMP 有一个支持进一步验证的反例，但一次差异不足以证明普遍收益。该成功率仅描述本批合成参数映射及已检查的控制条件，未运行 GX Works2 编译、真实变频器通信、RTC 或 PLC 扫描，不推广到 227 个形式或整个 FX 系列。

## 小范围解析与缓存修复

CML 的同页提取包含完整 `Word device number storing inverted data`，以及相邻单元格中的 `W | ord device number storing inverted data`。解析器只在同一来源记录、手册修订、PDF 页和显式原生符号的另一份表格表示给出精确完整文本时重建；分片原始位置保留在 `value_spans`，无空格连接以 `join_before: ""` 表示。否定词、单位、数值、页码或符号不同的反例不能作为重建证据。原有 Core 仲裁保持严格。

通过既有审计入口重跑 227 个形式、631 个槽位，得到 **27 个 source_verified、588 个 candidate_evidence、16 个 unresolved，221 个形式用途证据齐全**。相对[上一轮记录](2026-10-03-fx3u-operand-purpose.md)，CML、CMLP、DCML、DCMLP 恢复 8 个候选槽位；已验证数仍为 27。剩余桶为直接冲突 5、冲突单元隔离/未选择 5、未恢复表格 4、未绑定表行 2。未执行 promotion，也未覆写上一轮冻结审计摘要。

本次交付的 589 条候选 witness 均回查原始 `chunks.text` 的手册、修订、页范围与行/上下文区间，63 条跨行 witness 可重建原值。当前预算选择的 CML 行来自完整文本表示，交付 witness 中没有需要空格省略的字符拼接；该拼接的原始分片及其严格来源条件由解析回归覆盖。索引文件大小与修改时间未变。此审计仍位于共享检索上下文阶段，不能作为用途正确率或生成正确率。

Windows 损坏 SQLite 观察缓存的 `WinError 32` 独立修复：连接在读写、清理及异常返回时确定关闭，同时保留既有事务提交/回滚。四个入口的回归都在返回后立即删除损坏文件，不依赖垃圾回收或删除重试。
